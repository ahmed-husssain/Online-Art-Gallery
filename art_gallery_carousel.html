⚡ BOTTLENECK #2 • CONCURRENCY ANOMALY

The Double-Bid Anomaly:
What happens when 500 users
bid in the final second?

Standard web apps read the current bid, check if newBid > currentBid, and save. In high concurrency, two requests pass the check simultaneously — causing a critical lost update anomaly.

https://gallery.app/settings — security & transaction isolation
// The Race Condition Collision:
[T=14:02:11.842] Collector A bids $1,500 ➔ Reads Current = $1,400 (Valid!)
[T=14:02:11.843] Collector B bids $1,500 ➔ Reads Current = $1,400 (Valid!)
➔ BOTH OVERWRITE: Two winners, broken accounting, data corruption.

// The Fix Tested in Sprint 2:
➔ Benchmarking Pessimistic row lock vs. EF Core [Timestamp] RowVersion under 500 threads.
